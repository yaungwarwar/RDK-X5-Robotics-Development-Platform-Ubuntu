# Phase B.5 — staged physical acceptance plan

**Blocked.** The heatsink is ordered; its installation and continuous active cooling have not been confirmed. This document authorizes no target access, transfer, test, subscription or workload. Each new target activity needs its specified authorization and a safe stationary bench. Every preview authorization must cover immediate abort, cleanup and post-stop verification. The installed v0.1.3 service, existing camera process, systemd protections, generated Compose profile, ROS/DDS settings and historical backups must be preserved. No additional capture process may be launched. Do not begin Phase C from this plan.

Use this checklist for any future authorized run. The plan embedded in the immutable B.4.2 laboratory bundle predates these clarifications.

1. **Cooling gate:** the user confirms continuous active cooling is installed and operating and that no robotics operation will be interrupted. Record the cooling arrangement without changing fan firmware, kernel settings or thermal thresholds. Seek separate approval for read-only target preflight.
2. **Thermal stabilization gate:** with approval, check both CPU and DDR at or below **73 °C continuously for at least 60 seconds**. Missing readings abort. Check both again immediately before starting any scope or subscription; either value above 73 °C blocks start. During any authorized preview abort at **75 °C or higher** on either sensor, when either reading is unavailable, or if the installed monitoring service becomes unhealthy. Stop only owned laboratory processes. No threshold may be raised to obtain a pass.
3. **Existing-system gate:** verify v0.1.3 native backend and dashboard health/freshness, listeners, camera process identity, active generated Compose and available storage without restarting anything. Record a baseline for CPU/DDR temperatures, memory, tasks and processes. If the existing camera publisher is absent, stop camera-specific work and ask the user to operate the existing camera application manually.
4. **Bundle gate:** only after separate approval for target preparation, choose a fresh directory outside the installation and backups. Verify the local and transferred archive SHA-256, exact manifest and entries before any execution. Use a fresh isolated laboratory venv and offline wheel checks; native ROS worker remains `/usr/bin/python3`. Never modify vendor packages or copy the workstation venv. Binding is loopback-only and access uses a private tunnel.
5. **Isolation gate.** Before any image subscription, read the effective limits in the broker's actual scope and process. Record each observed value. Require all five matches below, verified loopback listener ownership, and a separately authorized external wall-clock deadline that covers both sessions and stops the owned scope. Block the test on a missing or mismatched limit. Verify the worker inherits the same process limits and belongs to that scope when it starts. Abort on mismatch.

   | Control | Required observed value |
   |---|---|
   | Combined broker and children, `memory.max` | 402653184 bytes (384 MiB) |
   | Swap, `memory.swap.max` | 0 bytes |
   | Tasks, `pids.max` | 64 |
   | Per-process cumulative CPU time, `RLIMIT_CPU` | 15 seconds soft, 16 seconds hard |
   | Open descriptors per process, `RLIMIT_NOFILE` | 128 soft, 128 hard |

   CPU-rate enforcement remains unverified. Approval must explicitly cover this limitation for the bounded run. Reduced priority and cumulative CPU time provide no aggregate rate guarantee. DDS/kernel buffers and browser decoding have costs outside the scope. See the [isolation observations](CAMERA_RESOURCE_ISOLATION.md).

6. **Left reconnect gate.** Obtain approval for two consecutive sessions on the left view only, with at most one live worker and subscription to each selected topic at a time. Start the first preview and confirm the browser decodes a real frame. Record type, QoS, dimensions, NV12 encoding, stride and available calibration. Stop on incompatible input. Issue Stop and immediately request Start again. Do not wait at the browser for worker exit or poll for an empty subscription list between requests.

   Record ordered evidence for first decode, Stop, reconnect request arrival at the broker, old-worker reap, new-worker start and a successful decode in the second browser session. Identify workers by PID and process start time, and correlate events on a common time base or by causal ordering. Record timing uncertainty. Pass the cleanup-race check only if the reconnect reached the broker while cleanup was pending, the prior worker was reaped before the next start, and a new frame decoded. If cleanup had already finished, record the successful reconnect separately and leave the race pending. If available evidence cannot resolve ordering or exclude worker overlap, mark that check inconclusive. Process samples alone can miss a short overlap. Record errors or decode failures as observed. Use the original authorized deadline and thermal/health aborts throughout, with no extension or automatic repeat. Retain event metadata only.

7. **Cleanup gate.** stop the owned viewer, worker, broker and tunnel; verify no lab listener, worker or image subscriptions remain, no child processes accumulate, the original camera process remains running, and v0.1.3 backend/dashboard remain healthy. Record actual results, resource deltas, frame counters and timestamp provenance; do not call an unobserved cleanup a pass.
8. **Right-camera gate:** a distinct authorization is required after reviewing left-test results. Repeat preconditions and inspect type, encoding, dimensions, stride, QoS and calibration before a bounded single-view preview. Stop on incompatibility and do not start another capture process.
9. **Combined-camera gate:** a distinct authorization is required. Repeat preconditions and assess actual raw or compressed publisher presence, compatibility, payload sizes and resources for one view. Absence is unavailable, not a discovery failure. No simultaneous multi-view subscriptions without separate approval.
10. **Sustained-resource gate:** a separate authorization must specify duration, safe thermal margin, thresholds, scope and abort conditions. Measure broker/worker CPU-time deltas and memory, DDS/process counts, bandwidth, drops, timestamps and health. Do not infer target CPU isolation or sustained safety from workstation benchmarks. Stop and clean up on any thermal, health or resource concern.

Physical rollback, BPU inference workload, right/combined performance, color rendering and sustained testing remain unvalidated. A locally verified bundle and synthetic tests do not constitute physical or production acceptance. At each gate, record pass, fail or pending with actual evidence; stop when prerequisites are unmet.
