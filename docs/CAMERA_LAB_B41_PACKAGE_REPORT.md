# B.4.1 standalone camera laboratory package

The private, local-only package is `private local laboratory bundle`, SHA-256 `7e25c1680f32860b103b4e2422a887c82f8bb9ecc328a816a697d5b1b02727fe`. Its companion `camera-lab-b41-b42-source-manifest.sha256` has **34 entries**; all 34 listed payload files and the embedded manifest were checked directly in the 35-entry archive and again after fresh local extraction, with no extra entries, duplicates or mismatches. The package directory is mode 0700 and the archive mode 0600. It is a development laboratory package, not a release or authorization to access the target.

It contains the exact current B.4.1 native worker, supervisor, IPC module and broker; the already-built laboratory frontend and referenced assets; selected laboratory documentation and the separately gated B.5 acceptance plan; pinned broker requirements; a newly generated hash-locked requirements file; and 17 pre-existing Python 3.10 ARM64/universal wheels. There are no ROS mock modules, synthetic test fixtures, virtual environments, credentials, target backups or release archives in the package. The worker/broker module bytes match the accepted working tree and compile successfully; built HTML references were verified. A local synthetic IPC exercise using the packaged modules verified frame receipt, cancellation ordering, worker reaping and reservation cleanup; its test fixture was used from the workstation and is **not in the package**.

The package includes B.1 NV12 grayscale luminance compatibility, the reconnect supervisor's shared reaping path, B.2 diagnostic handling, B.3 lab publisher/intrinsics reporting, and the B.4.1 narrow cancellation shield. B.3 backend startup changes belong to the existing dashboard backend, which is deliberately not included in this standalone lab. The 17 wheel files match those in the prior verified reconnect bundle byte-for-byte. A workstation `pip install --dry-run --ignore-installed --no-index --require-hashes` resolution for CPython 3.10 / manylinux2014 aarch64 selected all 17 pinned packages without downloads or installation. Cross-platform pip resolution does not reproduce every target environment marker or demonstrate executable ARM64 imports, native ROS, DDS, actual camera behavior or sustained resource limits. The new bundle has **not** been transferred or physically tested.

The first cross-platform dry-run invocation was rejected by pip because it omitted the required `--target` option; repeating it with a project-local target argument succeeded. No package was installed by either dry run. A first post-extraction `sha256sum` command used the wrong manifest filename; the embedded `SOURCE_MANIFEST.sha256` was then checked successfully against all 34 files.

The original v0.1.3 archive and source manifest and all three historical laboratory archives were preserved. The new package does not replace the earlier reconnect bundle. Physical testing stays suspended until continuous active cooling is confirmed and the relevant B.5 gates receive separate approval.
