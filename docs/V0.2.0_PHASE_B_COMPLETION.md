# v0.2.0 Phase B — standalone native camera laboratory

Phase B implements a standalone loopback laboratory, not an installed application or a physical acceptance. Native ROS2 selection starts the fixed-topic `/usr/bin/python3` worker only on explicit preview Start. The broker uses bounded v1 IPC and a single native-worker reservation, retains a latest frame, uses ACK-gated browser delivery, shows actual received calibration, and reports failure without substituting synthetic data. Left, right and combined raw views and combined compressed input are selectable. Raw support is `rgb8`, `bgr8`, `mono8`; compressed structural support is JPEG and PNG. Unsupported encodings and oversize or malformed messages are rejected. The existing production backend, graph discovery, systemd, Nginx and physical target were not changed.

Final local results: **235 Python tests passed**, **12 existing dashboard browser tests passed**, and **10 standalone laboratory browser tests passed**: 257 cases total. The QA runner includes three Node guard scenarios within one Python wrapper, not as extra counted tests. Strict pip check, Python Ruff lint/format, compileall, lab Prettier and ESLint, existing frontend lint/build, lab TypeScript/build, actual Nginx proxy/security/WebSocket validation, generated Compose CPU profiles and owned QA process/listener checks passed. One existing Starlette TestClient warning and non-failing browser color warnings remain. Results are from Ubuntu AMD64, synthetic fixtures and mocked ROS modules; the real worker was launched under system Python against those mock interfaces and real local subprocess IPC. See [native test report](CAMERA_NATIVE_TEST_REPORT.md).

Architecture and operational limits are in [native worker](NATIVE_CAMERA_WORKER.md), [IPC protocol](CAMERA_IPC_PROTOCOL.md), [encoding compatibility](CAMERA_ENCODING_COMPATIBILITY.md), [lifecycle](CAMERA_WORKER_LIFECYCLE.md), and [resource budget](CAMERA_RESOURCE_BUDGET.md). The separate [physical laboratory procedure](CAMERA_PHYSICAL_LAB_PROCEDURE.md) is prepared but must not be run without separate approval for physical camera testing/subscriptions. The original v0.1.3 archive and source manifest remain unchanged. No physical rollback was tested.

Before considering physical acceptance or deployment, separately authorize a stationary bench window, inspect actual publisher types, QoS, encodings, dimensions and calibration, then measure memory/CPU/bandwidth, cleanup, timestamps, temperature and telemetry continuity. The encoded payload and middleware buffers remain subject to target measurement; JPEG receives structural validation plus browser decode, not full native decode. OS-level worker memory/CPU limits have not been established. Authentication/TLS and existing physical limitations remain open. This laboratory is not production certification or a vehicle-control system.
