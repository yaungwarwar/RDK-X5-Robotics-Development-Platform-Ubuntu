# v0.2.0 Phase A — local laboratory prototype

Phase A delivered an isolated synthetic-only viewer and design for a future system-Python ROS2 worker. It did not deploy, subscribe to physical images, start a camera, modify the physical RDK, change the existing graph probe, or validate the camera hardware. The desktop/mobile viewer supports left, right and combined mock selection, explicit start/stop, mock labels, stale/disconnected state and bounded session metrics; real availability, calibration and native worker resource measurements remain unavailable.

The local results and commands are in [test report](CAMERA_PROTOTYPE_TEST_REPORT.md); diagrams and migration boundary are in [architecture](V0.2.0_ARCHITECTURE.md); [transport comparison](CAMERA_TRANSPORT_COMPARISON.md), [worker design](CAMERA_WORKER_DESIGN.md) and [resource budget](CAMERA_RESOURCE_BUDGET.md) describe tradeoffs and unverified assumptions. The existing QA runner now checks free ports, startup, Linux process/listener ownership during tests and cleanup; see [QA infrastructure](QA_INFRASTRUCTURE.md). The v0.1.3 archive and manifest were preserved. No physical rollback has been validated.

Proposed Phase B, subject to explicit authorization: implement and isolate the native `/usr/bin/python3` ROS worker and bounded IPC; inspect actual publisher type, encoding, QoS and calibration against the previously observed names; validate error handling and cleanup; integrate the preview behind explicit opt-in with loopback Nginx and existing security controls; measure target memory, CPU, bandwidth, frame age and telemetry continuity; develop v0.1.3 → v0.2.0 transactional upgrade/rollback to v0.1.3 without reusing historical transactions. No hardware capability, physical limits, safety certification or deployment is implied by synthetic results. Preserve open BPU sensor errno 110, missing authentication/TLS, `systemctl` output bound and ROS subprocess overhead.
