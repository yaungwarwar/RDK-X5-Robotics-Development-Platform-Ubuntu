# Camera worker IPC v1

A private child stdout pipe is the only worker-to-broker image channel; stderr is drained separately into a rolling 2 KiB tail for bounded diagnostics. The broker passes no commands over stdin. Each record is `uint32_be header_length`, `uint32_be payload_length`, UTF-8 JSON header, then payload. Maximum JSON is 4096 bytes; maximum binary payload is 2 MiB. Lengths are checked **before** reading the bodies; records must carry `version: 1` and a recognized `type`. Non-frame messages must have empty payloads, frames must have a payload. Invalid/truncated/oversized records, unsupported versions, EOF, or a 15-second missing record cause fatal disconnection and worker cleanup. JSON output must not be mixed with ROS logs.

`ready` declares the chosen view and topic. `frame` includes view, sequence, PNG/JPEG MIME, width, height, original encoding, optional ROS header stamp and calibration, worker replacement count and invalid-frame count, followed by image bytes. `error` reports a bounded error for an invalid frame; the worker may continue. `status` is a five-second heartbeat with the current publisher count; it carries no image. The broker validates view, MIME, image signatures, dimensions and body lengths before replacing its single latest slot. It does not treat IPC input as a command channel. ROS callback serialization, metadata integrity and decode costs are bounded but OS and ROS middleware buffering are not covered by the Python slot limit.

The browser protocol remains separate: one JSON frame descriptor followed by one binary image, then ACK only after browser image decode. There is one in-flight image per viewer, a two-second ACK/send deadline, and stale indication. Failed decode is shown as an error. No image is recorded. Native and synthetic never silently substitute for one another.
