During the 2026-11-25 maintenance window, preparation and activation of the native v0.1.2 → v0.1.3 upgrade both returned zero. The archive SHA-256 was `07cf0439383e6fc207ca47517ffeb62f56603be4fb136e08f42e15c31e6cd37b`. The 91 source-manifest entries matched at release verification. Original commands, endpoint details and transaction evidence are retained privately.

The ARM64 installation used an isolated Python 3.10.12 venv and passed strict dependency checking. The generated Compose profile retained 96 MiB memory and 64 PID limits, UID/GID 101, a read-only root, dropped capabilities and no-new-privileges. The service protections and loopback listeners were preserved. Disabling external ROS library logging allowed graph discovery inside the protected service.

## Observed stability

31 samples over 300.01 seconds all reported healthy, fresh native 0.1.3 with no collector error. Twenty-four distinct ROS2 discoveries succeeded, with 3.089–3.283 seconds per probe, zero failures and fresh graph data. Sampled process listings showed at most one ROS2 probe and no accumulating BPU temperature helper; service task count ranged from 4 to 21, including transient probe threads. No external logging initialization failure was seen in accessible service logs. The discovered graph contained the monitor node and `/parameter_events`; the existing camera was not running, so camera publisher acceptance remains pending.

Systemd service memory, which includes descendants, ranged 51.121–80.758 MiB (mean 58.459 MiB). A separate backend main-process RSS sample was 49,796 KiB (48.63 MiB). Frontend Docker memory was 2.023–2.070 MiB and sampled CPU 0.00–0.02%. Service CPU computed from elapsed CPU-time deltas was 13.591–34.553% of one core, mean 28.384%; it includes probe subprocess activity. These values are not directly comparable to prior figures without identical measurement methods. Collector duration ranged 0.024–0.110 seconds; CPU temperature 57.115–59.460 °C and DDR temperature 58.386–59.900 °C. All ratio samples were zero, agreeing with idle BPU utilization; dedicated temperature remained null with errno 110 and the CPU proxy remained separately attributed.

Through the SSH tunnel, an uninterrupted 300.71-second WebSocket session received 285 native v0.1.3 messages with advancing sequence numbers and no stale or collector errors. The dashboard HTTP response was 200.

At the final check the native backend and dashboard were healthy. Activation downtime was unmeasured.
