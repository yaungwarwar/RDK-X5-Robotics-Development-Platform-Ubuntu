# Phase B.2 — local camera diagnostic corrections

Phase B.2 corrects the local laboratory diagnostics identified in the engineering review. It is not a physical acceptance, deployment, or Phase C. Physical testing remains suspended until the user confirms continuous active cooling; the previously attempted reconnect did not start because the thermal precondition was not met. No RDK connection, monitoring, subscription, transfer, hardware modification or deployment was performed in this phase.

## Implemented

- `/lab/status` reports `inactive`, `synthetic`, `native`, or `mixed` for accepted concurrent sessions, their source set, and broker-lifetime ACK success, invalid and timeout counts. A failed handshake or cleanup releases the session entry.
- The viewer labels sent FPS and image-payload throughput as session averages; frame age is explicitly a lower bound since broker receipt, not camera capture age. Broker peak RSS/CPU and worker process RSS/CPU are identified separately; CPU is percentage of one core. The original field names remain for compatibility.
- Worker errors and readiness records use a separate bounded 16-record diagnostic queue so images cannot replace them. A full queue increments an overflow count carried in subsequent records. The broker has a separate 16-event diagnostic queue and sends an explicit overflow notice. The viewer retains the most recent diagnostic across subsequent frames. WebSocket error sends have a deadline.
- The pending-error/frame ordering failure was reproduced with a synthetic native supervisor: error and frame were ready together and no later event arrived. The broker now re-signals pending work after a diagnostic; regression verifies both arrive without a subsequent frame.
- Worker callback throttling and invalid-message counts, worker IPC-slot replacement, broker-slot replacement, successful browser ACKs and diagnostic overflow are separately observable. Invalid ACK and ACK timeout totals are available from status. Counters describe distinct stages, not all publisher or DDS losses.
- The existing single-native-worker reservation, shielded shared cleanup and reconnect waiting mechanism were preserved.

## Local validation

The complete suite ran with the persistent recovered Python, Nginx, Compose and existing Chromium. Results: **252 Python tests, 12 dashboard browser tests and 12 laboratory browser tests passed** (276 total). The six new Python cases cover source states, ACK success and invalid ACK, bounded broker and worker error queues/overflow, error-before-frame ordering, and throttling accounting; the existing timeout test additionally checks timeout accounting. The added browser case checks measurement labels on desktop and mobile; the native fixture browser case checks that an error remains visible after a later decoded frame. After a formatting-only change and the additional timeout assertion, the affected 17 focused Python tests passed again.

Strict `pip check`, Ruff lint and formatting, Python compilation, frontend and laboratory ESLint, Prettier, TypeScript and both frontend builds passed. The guarded QA runner validated both Nginx configurations, a real Nginx proxy, 12 API endpoints and WebSocket/security checks, and generated Compose profiles with and without CPU quota. Its owned backend and proxy shut down; no listeners remained on local QA ports 18088, 18089 or 18100. The existing Starlette TestClient deprecation warning, pip cache warning and non-failing browser color warnings remain.

## Integrity and limitations

The original v0.1.3 archive SHA-256 remains `07cf0439383e6fc207ca47517ffeb62f56603be4fb136e08f42e15c31e6cd37b`; its source manifest remains `aa0a8a7d724403344559d5df2da2d8cae69b469d1f341c812431b86cd1fa3f76`. All **91 manifest entries match the files inside the original archive**. The separately preserved reconnect-corrected bundle remains `71b3a00a8a2afab1f686d478eacccb1a1b9fca227beb46b3a765546bdd1aa7e3`; it does not contain the new Phase B.2 changes and was not regenerated.

Bounded queues cannot guarantee delivery of every diagnostic during unlimited error floods, after disconnection, or if the worker is terminated; explicit overflow counts expose queue saturation when records can be delivered. ACK totals are process-local and reset on broker restart. A displayed age excludes upstream capture, conversion, IPC and network/decode time; source timestamp clock provenance remains unverified. RSS and CPU do not include all descendants, kernel/DDS allocations or browser memory. No CPU-rate quota was available on the physical target, and per-process CPU-time limits do not provide one. ROS/DDS can allocate before application validation. Physical reconnect, right/combined previews and sustained resource behavior remain untested. No physical acceptance, target health recheck, production certification or deployment readiness is claimed.
