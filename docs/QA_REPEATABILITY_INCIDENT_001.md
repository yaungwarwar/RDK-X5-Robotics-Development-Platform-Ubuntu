# QA repeatability incident 001

The independent B.4 QA run reported 266 Python passes and one failure in `test_broker_native_ipc_frame_calibration_and_disconnect`; subsequent required QA stages did not run and the runner correctly returned failure. Starlette's WebSocket TestClient context-manager exit raised `concurrent.futures.CancelledError`. Before re-execution, its report, associated JUnit XML and available run directory were copied to the ignored local `qa-results/incident-001-original/` evidence directory, alongside interpreter/dependency versions and environment-variable presence flags. No independent console log was present in that run directory; the JUnit traceback and structured report are preserved. Environment presence was recorded after the incident, not assumed to describe the original shell.

## Reproduction and diagnosis

One isolated test and 30 additional fresh-process isolated executions all passed. Five complete native-camera module runs also passed before the correction. Running 200 synthetic TestClient sessions within one process reproduced the original exception once, at iteration 3. An instrumented run reproduced it at iteration 200: its ASGI traceback shows `WebSocketDisconnect` detected in `wait_for_frame_or_disconnect`, followed by `asyncio.CancelledError` interrupting that function's `finally` while it awaited `asyncio.gather` to reap its two helper tasks. Starlette TestClient sends a disconnect and then immediately cancels its session cancel scope during context exit; the two actions can race. The interrupted helper cleanup replaced the already-detected disconnect with cancellation, and the TestClient portal future exposed the cancellation at `__exit__`. This mechanism is confirmed for the instrumented reproduction. The original JUnit failure did not capture the internal ASGI traceback, so attributing that specific occurrence to the same mechanism is strongly supported but not independently proven. No physical-device failure is claimed, and other TestClient cancellation paths may exist.

The deterministic synthetic regression holds the helper-task gather at a synchronization point and cancels the surrounding AnyIO scope after the disconnect has been detected. Running that test against a locally reconstructed pre-fix helper fails the disconnect assertion; it passes with the correction. The original trace, per-run logs and deterministic pre-fix evidence are under `qa-results/incident-001-original/`. No dependency upgrade was performed.

## Correction and verification

The broker now shields only cancellation and reaping of the two helper tasks in `wait_for_frame_or_disconnect`. It does not globally suppress cancellation; the existing shielded shared native-worker cleanup, reservation until reaping and fail-closed behavior remain in place. Synthetic tests exercise the deterministic cancellation ordering, cancellation of one shutdown waiter while another shares cleanup, and a real local Uvicorn/WebSocket session that verifies worker reaping, no reservation or helper-task leakage and session cleanup.

Repeatability results and artifact verification are recorded in [Phase B.4.1 completion](V0.2.0_PHASE_B41_COMPLETION.md) and `qa-results/incident-001-validation/`. Repeated executions are repeatability evidence, not additional unique cases. No physical target was contacted.
