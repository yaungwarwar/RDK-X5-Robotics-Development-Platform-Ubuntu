# Phase B.3 — local robustness and synthetic benchmark

Phase B.3 reproduces and corrects the review findings described in [backend startup robustness](BACKEND_STARTUP_ROBUSTNESS.md) and the [findings register](ENGINEERING_FINDINGS_REGISTER.md). Initial auxiliary failure now yields explicitly unavailable ROS/camera/service sections instead of HTTP 500. Auxiliary graph and service failures are isolated from each other. Executor cleanup waits off the event loop. Production host defaults and laboratory WebSocket hosts exclude test-only names. The dashboard rejects incomplete telemetry without inventing readings and has a tested error boundary.

The camera laboratory now describes K-matrix availability as **intrinsics present**, not independently validated calibration. Native worker publisher heartbeat counts are validated and passed to the browser, distinguishing zero publishers from a publisher that has not supplied a usable frame. No additional ROS graph discovery or physical subscriptions were added. Existing bounded queues, frame and IPC validation, single-worker reservation and cleanup remain in effect.

The [synthetic NV12 benchmark](CAMERA_LOCAL_RESOURCE_BENCHMARK.md) includes low/high detail, conversion CPU and wall samples, sampled peak RSS, payload sizes, Chromium decode and a separate IPC/broker/ACK/diagnostic/cleanup exercise for each configuration. Its raw per-iteration results are retained separately. High-detail baseline median was 22.577 ms CPU, 22.592 ms wall time and 1,394,408 bytes; half-resolution median was 7.420 ms and 348,973 bytes on this workstation. These are neither target measurements nor a reason to change defaults. The experiments do not measure actual timed browser delivery, live DDS loss or sustained physical load.
