# Phase B.4.1 — cancellation repeatability correction

The independent B.4 run failed one native-camera TestClient teardown, and its original structured report and JUnit traceback were preserved before reruns. The [incident report](QA_REPEATABILITY_INCIDENT_001.md) describes the confirmed cancellation mechanism in an instrumented synthetic reproduction and the remaining uncertainty about the original occurrence's unrecorded internal ASGI stack.

The broker now shields only helper-task cancellation and reaping after a frame/disconnect wait. It does not globally suppress cancellation or alter worker reservation, shared cleanup, frame limits, bounded diagnostics or WebSocket security. A deterministic event-controlled regression fails against the reconstructed pre-fix helper and passes after the correction. Additional synthetic tests cover cancellation of one shutdown waiter while a second shares the same cleanup and verifies reaping, plus a real local Uvicorn/WebSocket connection with a synthetic subprocess, disconnect and cleanup before and after server shutdown. No sleep delay or retry was added to conceal the issue.

## Actual repeatability results

Before the correction, the affected test passed once in isolation and 30/30 additional fresh-process attempts, and the module passed 5/5 runs. A separate same-process stress reproduction saw the same TestClient exception once in 200 sessions; an instrumented reproduction captured its internal cancellation traceback at iteration 200. Every fresh-process pre-fix attempt and the stress traces are preserved under `qa-results/incident-001-original/`.

After the correction:

|---|---:|---:|
| Affected test, fresh Python process | 50/50 passed | 0.493–0.510 s |
| Entire native-camera module | 10/10 passed | 1.839–1.929 s |

| Unified QA run 2 | passed, zero skips | 88.44 s of stages |
| Unified QA run 3 | passed, zero skips | 88.33 s of stages |

Each full run executed the same **270 Python, 16 dashboard browser and 16 laboratory browser cases: 302 unique cases**, not 906. All required checks passed in every run, including strict dependency validation, static checks/builds, real Nginx proxy and WebSocket checks, both Compose profiles, listener ownership, cleanup and artifact hashes. Python emitted the existing Starlette TestClient deprecation plus local Uvicorn/websockets legacy deprecation warnings introduced by the real-socket regression; pip cache and Playwright color warnings remain. No dependencies were upgraded.

Per-execution exit codes, durations and console output are in `qa-results/incident-001-validation/repeat-results.json`, its numbered logs, and the separately retained `qa-01`, `qa-02` and `qa-03` structured reports and logs. The original failed `qa-results/qa-report.json` was not overwritten and is byte-identical to its preserved copy.

Later B.4.2 note: a subsequent independent user validation updated the root `qa-results/qa-report.json` to a passing result. The originally failed report and JUnit traceback remain preserved in `qa-results/incident-001-original/`.
