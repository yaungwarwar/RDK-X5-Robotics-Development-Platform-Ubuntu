# Local camera laboratory engineering review

Review scope: workstation source and synthetic fixtures only. No connection to the RDK, temperature monitoring, image subscription, production-code modification, or release regeneration was performed. The last authorized physical reconnect attempt did not start because the thermal precondition was not satisfied. All physical camera testing is suspended until the user confirms continuous active cooling is installed. Physical reconnect is **not validated**.

## Findings

1. **Incorrect status source (confirmed defect).** The `/lab/status` endpoint always reports `source: synthetic` ([server.py](../prototype/camera_lab/server.py#L31)), including while a native-source session is active. In a local TestClient session using the fake native IPC child, a frame reported `source: native` while the same session's status endpoint reported `source: synthetic`; the fake child was cleaned up. This can mislead monitoring consumers; it is not evidence that the viewer silently falls back to synthetic frames. No correction was made because the user requires separate approval before modifying production code.
2. **Frame-age and throughput labels need qualification.** The broker timestamps a native frame when it enters its latest-frame slot, not when the camera captured it ([server.py](../prototype/camera_lab/server.py#L88)); the age displayed does not include acquisition, conversion, IPC or browser decoding. FPS is the cumulative count sent divided by session elapsed time and includes startup; it is not camera publisher FPS or a current rolling rate. Bandwidth is image payload bytes per second, excluding protocol overhead ([server.py](../prototype/camera_lab/server.py#L198)). The UI's generic labels do not make these boundaries clear. Source timestamps are forwarded separately; their clock provenance has not been validated.
3. **Dropped/error counts are incomplete.** Broker drops count replaced latest-slot frames; worker drops count replacement in its single-slot IPC queue. They do not account for DDS loss or intentional pre-conversion throttling ([native_worker.py](../prototype/camera_lab/native_worker.py#L258)). Errors and frames share the worker's single-slot queue ([native_worker.py](../prototype/camera_lab/native_worker.py#L194)), so a queued error may be replaced before transmission. Also, code inspection indicates that a frame arriving while an error event is pending can remain in the slot after the broker clears the event and handles the error ([server.py](../prototype/camera_lab/server.py#L215)); delivery may then wait for a subsequent event. That ordering is a review inference, not a reproduced failure. Invalid-frame totals accompany later frames, but do not guarantee delivery of each error. Dedicated synthetic ordering and backpressure regression tests are needed before considering this resolved.
4. **Resource figures are not whole-scope accounting.** Worker RSS and elapsed CPU-time deltas read the individual worker's `/proc` records ([native_supervisor.py](../prototype/camera_lab/native_supervisor.py#L35)); they do not include descendants, kernel DDS buffers or the remote browser. The field named `lab_peak_rss_kib` is broker-process peak RSS, and `lab_cpu_pct` is broker process CPU over session elapsed time, not aggregate lab usage ([server.py](../prototype/camera_lab/server.py#L261)). CPU is percent of one core and may exceed 100%; short sampling intervals and process startup affect precision. An external scope-level memory measurement and separate broker/worker CPU-time deltas are needed for a complete report.

## Lifecycle, limits and coverage

The native supervisor reserves a single worker, waits for an already-stopping worker, uses shielded shared cleanup, and escalates termination to kill before releasing the reservation. If the child cannot be reaped it fails closed rather than admitting another worker. The local tests cover a stubborn mock process and immediate reconnect, startup failure, crash/heartbeat timeout, disconnect during startup, synthetic stream switching and slow clients, and fake native IPC with disconnect. These establish tested local behavior only; they do not establish physical reconnect, physical middleware cleanup, or sustained-load stability. The QA process guard regression also passed locally.

The previously observed physical scope enforced a combined 384 MiB memory limit, zero swap and 64 tasks, with inherited per-process CPU-time and file-descriptor limits. The available user cgroup did **not** provide a verified CPU-rate quota; `RLIMIT_CPU` is per-process cumulative time and `nice` is not a quota. Broker and worker do not have independent memory budgets. ROS/DDS may allocate a message before application validation, and kernel middleware and remote browser memory are outside the lab scope. One latest frame per slot, bounded IPC payloads and DDS depth one limit application buffering but do not guarantee real-time isolation. Do not relax limits or infer sustained safety from the short previous preview.
